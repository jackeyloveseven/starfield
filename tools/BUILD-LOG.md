## 配乐

`music/synth.py` 是引擎，`music/tune.py` 是**实际渲染入口**（先分源测量再解电平，然后编码）。

```bash
cd music && python -I tune.py out && python -I profile.py "out/*.mp3"
```

`tune.py` 的做法：分别只渲染低音 / 声部 / 微光三条源，量出各自的绝对频段功率（混响是线性的，功率可加），
再搜出三者的比例使混音的频段份额对上目标。直接盲调会在「全是中频」和「全是低频」之间来回摆。

目标曲线（候鸟实测 → 星空目标）：sub .25→.34-.40，high ~.003→.030-.055，air 0→.010-.025，
L/R 相关 .85→.42-.62，混响 rt 3→5.5-8s，和声 1-2s→4-8s 一变。

**当前状态**：sub / lowmid / mid / high / 相关度 / 响度基本到位；
**空气段（4-11 kHz）仍偏低**（实测 .002-.005，目标 .010-.025），centroid 也偏暗一点。
56 kbps 不是原因（编码前后一致），是微光声部上泛音的能量还不够。

## 第二版修订（用户试玩反馈）

用户报「严重屏闪 + 鸟被吸进黑洞 + 薄纸片没有星系感」。**我第一轮的两个诊断都错了**，是测量纠正的：

| 我的假设 | 测量结果 | 结论 |
|---|---|---|
| 星云纹理在渲染循环里生成、缓存无上限（理论 1.2 GB） | `frame.py`：跨 8 个区带只生成 **4-18 张**（量化后实际上限 30） | **不是屏闪主因**，但确实该封顶，已改 |
| 纸面俯仰透明度造成整片跳变 | 平飞时 pitch 漂移只让 alpha 变 ±0.06 | 次要，已改为恒不透明 |

**真正的主因**：`grav.py` 量出捕获过场每 200 秒触发一次、**8.7% 的时间处于捕获态**，每次是全屏白闪 + 船队被强行拖拽 13 秒。用户说的「屏闪」和「鸟被吸进去」是同一个现象。

还有一个我自己引入的 bug：`nebulaTex` 里写的是 `rawStyles[idx].tree`，那是**十六进制字符串**不是解析后的数组，`blend()` 算出 NaN，`css()` 生成非法颜色，canvas 静默保留上一个 fillStyle —— 结果**整个天空变成饱和绿**。改成 `styles[idx].tree` 后恢复。

修订内容：黑洞移到航线侧方 760-1180；捕获需要「距离够近 **且** 你在主动往那边引」（`|wind.x|>.18` 且方向一致；若黑洞几乎在正前方则要求任一方向有持续输入）；捕获加 26 秒超时兜底；白闪强度 .94→.62；纸鹤换成折纸飞船舰队；新增旋臂星系印版；薄纸片 7-14→1-2、印版 2-5→1-2 并压暗。

## 第三版：从「风景」改成「宇宙」

用户第三次说「不像宇宙，很简陋，行进路线是一个棋盘」。这次找到了结构性的原因，不是参数问题。

**根因**：`deepfield()` 在 y=−2 铺了一张 ±100000 的不透明平面，再按 **900×940 的格子**每格随机取 6 个色场之一 —— 那就是字面意义上的棋盘；它给每一帧压了一条地平线，于是所有画面读起来都是「在桌面上飞」。它上面还有一条「路」（bank + water 每 170 单位一段）。整套东西是从 候鸟 继承来的，在那里「鹤群下方是一格格田地」完全正确，在太空里不可能对。

**改动**（`v4_space.py` → `v4k_band.py`，每步都跑语法检查 + 截图）：

| | |
|---|---|
| 地面 | 整块删掉：平面、格子、路、`laneW`、`flatQuad`、`hatchCorner`、`lanePoint`。纸从「地板」变成「画面本身」——一张星图 |
| 全天球 | 星、亮星、星云的仰角原本采样在 `[0, 1.5] rad`，**只有上半球**——这正是当初需要一块地板挡住下半屏的原因。改成 y 均匀采样 |
| 银河带 | 走廊的路线标记。见下面「银河带」 |
| 印版星球 | `drawWorld()`：屏幕空间圆盘 + 受光渐层 + 明暗界线 + 暗面排线。原本只是 `glow()` + 一个星芒，看着像噪点 |
| 黑洞 | `drawHole()`：阴影 + 光子环 + 吸积盘，**远侧被引力抬到阴影上方**，多普勒一侧更亮。全部屏幕空间 |
| 引力透镜 | 爱因斯坦半径改为随黑洞投影半径缩放（`θ_E ≈ 1.35 r_shadow`），偏折 `θ_E²/r`，作用范围 6 个爱因斯坦半径（原本固定 4200/r、110px 上限、360px 截断） |
| 重力 | `updateBirds` 里只有 `kind===4` 对飞船施力，`GRAV` 1.35e8 → 1.6e7 |
| 捕获闪光 | 全屏 `fillRect` @ .62 alpha 白 → 以黑洞为中心的有界径向光晕 |
| HUD | `ALT 182 M` → `19.4 KLY` |

### 量到的两件事

**重力把船队撕开了**（`feel.py`，新工具）：修之前 `maxRadius 3238`、`avgRadius 755`、53% 时间超过 400 —— 静止半径是 276。600 单位外一颗中型恒星给 ~300 units/s²，而队形弹簧只有 75–180，所以恒星比队形拉得还狠。修之后 `avgRadius 269`、`maxRadius 465`、超 400 只占 1.3%。

**捕获仍然只由主动操舵触发**（`captest.py`）：操舵 600 秒 3 次、最近 85 单位；不操舵 600 秒 0 次。

### 银河带：三次猜错，最后靠量

带子做出来看不见。依次排除了「不够亮」（不是）、「被 `bw` 门控」（`bw` 恒 > .08），最后用 `bandprobe.py` 打出投影坐标才看清：**`forward = (−0.178, −0.963, 0.202)` —— 镜头有 74° 时间是俯视船队的**，而带子锚在世界地平线上，等于永远在画面外 90°。改成每帧从相机基底重建带子平面。

顺带查出一个既有 bug：`region()` 在 `t` 恰好为 0 或 1 时返回 `pureStyles[i]`，而 `pureStyles` 里的 `front` 恒为 0 —— 所以 `deepfield()` 的走廊辉光和 `drawSky()` 的地平线辉光在**纯色区带里根本不画**（`intensity` 算出 0）。

**诚实说明**：带子现在是**跟着镜头走的**（skybox 式的取巧），不是世界空间里的固定结构。转向时它会跟着转。要改成世界空间需要按区块生成星点，没做。

### 黑洞照 Gargantua 的结构重做（`v5_shape.py`）

原来是 2.5 倍阴影半径宽、0.16 倍厚的七层套嵌椭圆——一个胖环。真正的 Gargantua 是**几乎侧视的薄盘**：

- 阴影 + **极细的光子环**（`rad*1.055`，lineWidth `rad*.022`，全画最亮的东西）
- 薄盘本体，`b = a*.05`（原来 `.16`）
- **远侧被引力抬到阴影上方**，两层（`-rad*1.19` / `-rad*1.33`）
- **下方更暗的次级像**（`+rad*1.05`）
- 多普勒：整条盘一侧亮一侧暗（横向渐层，峰值在 26% 处）

### 星球改成雕版球面（`v5_shape.py` → `v5c_engrave.py`）

原来是「一大团平滑高光 + 横贯整盘的平行直线」——台球。改法：

- 光源**略微偏离视平面**（`L=[-.44,-.56,.44]`）。光源正好在视平面内时，纬度圈投影成**直线**；倾斜之后它们才弯。
- 排线用**绕光轴等角度的圆**——那才是跟着球面走的曲线。
- **只排夜面**：铺满整盘的圆看起来是**线框地球仪**，不是明暗（第一版就踩了这个）。
- 明暗界线 + 受光边缘的**大气环**（`rad*.965`→`rad*1.13` 的环带，按光的方向偏移）。

## 第五版：照参考图对齐（`v6_detail.py` → `v6b_disc.py`）

用户这次给了两张参考图（星际穿越的 Gargantua 剧照、马头星云的真实照片），并说星云/恒星带已经到位，**黑洞和星球要更精细**。

### 黑洞：从「平滑色带」改成「流动的气体」

看了剧照才发现之前错在哪：**盘不是一条平滑的细带**，是一片**宽的、纤维状的、湍流的**气体片——内缘过曝成纯白，中段琥珀，外缘铁锈色。之前那种平铺渐层填充，所以看着像画的而不是气体。

- 径向色阶：白热内缘 → 琥珀 → 铁锈（原来只有横向多普勒渐层）
- **纤维条纹**：每片 22 条沿盘流动的短弧，长度/半径/亮度/粗细全部 hash 随机，亮度再乘多普勒
- **远侧改成弧**：之前把远侧画成一条又扁又宽的**椭圆**，看着像第二个盘。剧照里它是**贴着阴影上方弯过去的一道弧**（和阴影同心），在两侧与直射像相接
- **只让盘的近侧压在阴影前面**：之前把整个椭圆在阴影之后重画一遍，等于远侧也跑到前面了——所以读起来是「一块板」而不是「一个环」。现在用 `rect` 裁剪，只让 `y > ry` 的那半重画

### 星球：加表面条带

球面本身已经像球了，但太干净。加了 9 条**绕行星自转轴**的纬度带（`PU`/`PV` 基），用粗描边画成带子，明暗按 `hash` 变化——一眼就是「有表面的大行星」。

### 星云：加暗尘

参考的马头星云是**发光气体 + 挡在前面的暗尘**。原来的 `nebulaTex` 是纯叠加发光，没有暗结构，只是一团污渍。加了 8 个 `destination-out` 的暗斑，在星云纹理里打出暗通道。

同一个错犯了三次：**新写的代码块结尾写成 `}};` 而不是 `}});`**（`queue.push({...fn:()=>{...}})` 少一个右括号）。`node --check` 每次都抓到了，没有写坏过文件，但浪费了三轮。
另外 `drawWorld` 里新加的 `ax` 和大气环那段已有的 `ax` 撞名，`const` 重复声明——已改成 `pax`。

## 第六版：沉浸感 + 照参考渲染器对齐（`v7_immersion.py` → `v8b_flare.py`）

用户：「太跳脱了，没有沉浸感」＋ 给了一个参考渲染器 `https://nrcl9jj7vmo8s.space.mcode.cn/`（GARGANTUA，史瓦西零测地线实时渲染）。

### 跳脱 = 一次 2600 单位的瞬移（`motion.py` 量出来的）

新工具 `motion.py` 每模拟帧采样相机基底，报出帧间位移最大的时刻：

```
max eye jump per frame : 2689 units   ← 捕获相位 3，600 秒里出现 3 次
其它一切               : < 43 units
```

根因：`updateCapture` 相位 3 里的 `travel+=2600` —— 一帧之内整个世界跳 2600 单位（正常是 2）。改成**衰减的速度爆发** `warp=28`，`warp*=exp(-dt*1.16)`，同样的距离但是**走过去的**。修完：

```
max eye jump per frame : 51 units    （降了 53 倍，且是一串连续的帧）
```

### 黑洞：照参考渲染器的着色模型算，而不是画

那个页面把整套参数暴露在配置里，直接读出来照着实现：

```
T(r)  = diskTemp * (diskIn/r)^tempExp      ~7400 K 内缘
flux  = (diskIn/r)^1.55                    亮度随半径快速衰减
eIn   = smoothstep(diskIn, diskIn*1.14+.06, r)
eOut  = 1 - smoothstep(diskOut*.74, diskOut*1.04, r)
flick = 1 + flicker*.5*(sin(t*.42 + r*2.1) + sin(t*.23 - r*1.3))
col   = blackbody(T*gt) * flux * dens * eIn * eOut * flick * pow(gt, beaming)
```

`diskIn=1, diskOut=28~34` **史瓦西半径** —— 1 阴影半径 ≈ 2.6 Rs，所以盘的直径是阴影的 **6.5 倍**，比我原来的 3.3 倍宽一倍。`blackbody()` 是 Tanner Helland 近似（页面里的原函数，照抄）。有了温度曲线，「内缘白热」才是**算出来的**而不是画上去的。

还渲染了参考页面本身做对比（headless + SwiftShader，**800×450 要 8 分钟**，1600×900 跑不完）：

```bash
chrome --headless=new --enable-unsafe-swiftshader --use-angle=swiftshader \
  --virtual-time-budget=20000 --window-size=800,450 --screenshot=ref-bh.png <ref_page.html>
```

对比出来两点差异：盘是**外扩的**（越往外越厚，边缘是宽而柔的一片，不是平带），以及**多普勒要下狠手**（迎向侧比背离侧亮好几倍，不是温和的渐层）。

### 星云：更游戏化

`nebulaTex` 的染色原本是 `blend(tree, 白, .42)` —— 42% 冲白，把墨色洗成灰。改成 `blend(blend(tree, alt, .38), 白, .14)`，`alt` 按星云自己的 seed 在 `water`/`sun`/`craft` 之间轮换。缓存键本来就带 seed，所以纹理数量不变（6×5）。

## 第七版：扁平化（`v9_flat.py`）

用户：「视觉上美学太差很丑，扁平化可以吗，星球让你改三遍了一点没变，去参考戴森球计划」。

**「改了三遍没变」是对的**，而且原因很清楚：我三遍都在**加**表面结构（雕版排线 → 纬度带 → 大气环），而屏幕上星球只有那么大，那些东西在那个尺寸下就是**噪点**，不是细节。加得越多越脏。

看了 DSP 自己的官方截图（Steam 公开 API 取的 promo 图，只当风格参考，没有拆包也没有反编译）才发现方向反了：**它的星球是光滑的浅色球** —— 一个亮的日下点、**很宽的柔和明暗界线**过渡到黑、受光边缘一道亮边，**几乎没有表面细节**。

所以这一版是**删**：

- 删掉雕版排线（整段）
- 删掉纬度带（整段）
- 删掉硬边
- 留下：日下点渐变 + 三条低对比云带 + 受光边缘的亮环 + 外层大气光晕

黑洞同一轮把盘调白：`TEMP 7400→9600`、`TEXP .75→.82`、`flux` 指数 `1.55→1.95`（外层衰减更快）。原来的盘太橙，参考里可见的盘是白到米色。

### 工具上的一件事

`}};` 少一个右括号这个错**一共犯了五次**（新写的 `queue.push({...fn:()=>{...}})` 结尾）。第五次之后在 `v9_flat.py` 里加了守卫：写文件前检查 `'}};\n}'`，命中就退出。**写新补丁脚本时都该带这一句。**

## 第八版：不是塑料球，是受光的球（`v10_lambert.py` → `v10h_lensed.py`）

用户：「v9 很塑料」。

**根因**（起了 4 个独立诊断 agent，回来的三份**各自独立地指向同一条**）：旧的 `drawWorld` 画的是一个**径向渐变**，圆心在日下点。径向渐变的等亮度线是**同心圆** —— 那正是「光滑球体 + 高光点」的视觉签名，也就是台球。再叠上 `[.84, 1.02] rad` 的一圈硬环（车出来的箍）和一圈墨色描边，**三个同心圆线索叠在一起**。

**正确的东西**：Lambert 球面 `b = x·lx + y·ly + z·lz`（`z = sqrt(1-r²)`）的等亮度线是**椭圆**不是圆 —— 中心沿光方向偏移 `b·sinθ`，半轴 `(cosθ, 1)·sqrt(1-b²)`。画这个场才是「受光的球」。推导见 `v10_lambert.py` 的 docstring。

**做法**：光不动、场是尺度无关的，所以整张场**烘一次**进 320² 的离屏 sprite，每个天体就是一次 `drawImage` + 一次 `multiply` 上色 —— 跟场画多细无关，每帧成本恒定。

后面七版都在修它引出来的问题：

| 脚本 | 修什么 |
|---|---|
| `v10b` | **太亮太白像灯泡**：ramp 指数 `.50` 把整个受光面顶到 95%，没有渐变只有白加悬崖。Lambert 亮度本来就是 `b`，改成近线性；multiply 上色从白 62% 降到 40%；大气光晕收窄调淡 |
| `v10c` | **天体太光秃**：加天气。旧的「三条水平椭圆带」在这个尺寸下读成环（又是同心圆的错），换成**不规则的软斑**，并按该点实际受光量淡出 —— 夜面的云是 bug 不是云 |
| `v10d` | 放大 3 倍看出两个瑕疵：云比它所在的受光面**更暗**（云色 72% 白，受光面 multiply 后是 40% 白 + ramp，实际更亮），合成出来是**灰污渍**；受光亮边是三道描边弧，离开球体浮在外面像**贴纸** —— 整段删掉，让外层光晕交代边缘（DSP 的球面上根本没有 rim light） |
| `v10e` | 光晕收尾太干脆，读成一块灰垫子，往外拉长调淡 |
| `v10f` | 黑洞的「纤维」是**过长的横条**：`len` 最大 `.64` × `ROUT` 6 个阴影半径 = 单根 3.8 rad，rad=100 时是 380px 的横杠，alpha 到 `.56` —— 读成 UI 扫描线。改成 54 根、更短更细更淡 |
| `v10g` | 吸积盘是套嵌半透明椭圆，**边缘累积成横带**（相邻环的台阶是 `a_k·(1−已累积)`，不会因为剖面平滑就变小）。环数 26→44，累积提前饱和，带子退到看不见的暗边 |
| `v10h` | 引力抬升的远侧弧是 10 道描边椭圆弧，切向处相邻半径比线宽还近 → 挤成**梳齿**。换成同一条环带上的**径向渐变**，没有硬边，而且是圆不是扁椭圆，跟阴影（也是圆）一致 |

### 这一版的教训

**「同心圆」是塑料感的唯一来源。** 径向渐变、正圆环、正圆描边，三样都是。修的过程中我三次差点又用同心结构去修它（水平云带、边缘亮环、lensed 离散弧），每次都读成同一个错。

## v103–v104：把「帧率低」拆成三种原因

「允许 GPU 加速，现在帧率低得不像话」这句话对应三个互不相干的原因：

1. **画布多走了一次合成。** `getContext('2d',{alpha:false})` 没有 `desynchronized`，缓冲要先交回
   合成器再上屏；加上之后可以直接从绘制缓冲合成。
2. **APK 里强制了一个硬件层。** `webView.setLayerType(LAYER_TYPE_HARDWARE, null)` 会把整个
   WebView 塞进单个 hardware layer，每帧 canvas 更新都要重传整层 —— 很多设备上这比默认路径
   慢一半以上。硬件加速由 `android:hardwareAccelerated="true"` 提供，`setLayerType` 删掉。
3. **分辨率是死的。** 之前的 DPR 在启动时按画质档位定死，设备扛不住就只剩掉帧一条路。现在
   每 3 秒量一次真实 fps：<45 按 0.15 步长降 `qualityScale`（下限 DPR 1.0），>57 连续 5 个窗口
   再放回去。**先降分辨率，再谈掉帧** —— 合成器放大比卡顿难看出来。

顺手修掉一个一直没回头的问题：`lowQuality` 只要连续 3 个窗口 <25fps 就置 true，**之后再也不会
变回 false**，一次卡顿会让整场星空永远变稀。现在每个窗口重算（触摸设备仍强制走轻量路径，这是
有意的）。

`icon.py` 一并入库：环带按半径的高斯剖面逐像素算，不是描边圆弧；亮度按方位角不对称
（迎面白热、背面余烬）。补了 `mipmap-anydpi-v26` 自适应图标与 monochrome 单色图标 ——
没有它们，Android 8+ 会把旧 PNG 缩进一个白圆里。

## v105–v106：按 GPU 分档，而不是「一个上限管所有设备」

同一份文件要跑在天玑 9400+（Mali-G925）、4K 屏的核显、5070 Ti，以及 SwiftShader 上。差别不在代码路径，
只在**每帧画多少像素是合理的**，所以只让 DPR 上限随 GPU 走：

| 渲染器串 | 档 | DPR 上限 |
|---|---|---|
| Mali / Adreno / PowerVR / Immortalis / Apple GPU | `mobile` | 1.75 |
| Intel / Iris / UHD / Radeon(TM) Graphics | `igpu` | 1.6 |
| GeForce / RTX / Radeon RX / Arc | `dgpu` | 2.0 |
| SwiftShader / llvmpipe | `cpu` | 1.0 |

探测一次、读完就释放上下文；`?gpu=mobile|igpu|dgpu|cpu` 可以在没有对应硬件时验证分档。
黑洞着色器的上下文补上 `powerPreference:'high-performance'` —— **不写这一条，混合显卡笔记本
可能把 WebGL 放到核显上**，而这正好是「拿着 5070 Ti 跑核显」。

## v107–v108：60 不是代码的上限，是屏幕的

`frame()` 由 `requestAnimationFrame` 驱动，浏览器把它锁在**屏幕刷新率**上：60Hz 屏就是 60，
120Hz 手机就是 120，144/240Hz 显示器就是 144/240 —— 只要一帧塞得进 8.3 / 6.9 / 4.2 ms。
浏览器不会让网页跑到 300fps，这是合成器的 vsync，不是页面的限制。

真正的问题在自适应：它拿 57fps 当「够好了」，于是 120Hz 屏上 70fps 就被判定为达标，永远不去够
面板的真实上限。现在启动后数 90 帧测一次刷新率（中位数，夹到 60–240），自适应目标改成
`target = hz × 0.92`，低于 `target×0.75` 降分辨率、高于 `target×0.95` 连续 5 个窗口再升回去。
刷新率也进了 `getState()`（`hz`），每台设备都能自己验。

## v113–v115：弦乐不再像唢呐，触控做减法

**音色**：古典点播的「小提琴」是双失谐锯齿 + `peaking 2850Hz Q3 +6dB`。那个频段正好是唢呐的鼻音
共振——带锯齿的激励源加上基频两个八度上的窄提升，定义上就是中国双簧管而不是弓弦。修法是减不是换：
2850Hz 从 +6dB 改成 -3dB 的谷、低通上限 4.2k→2.6k、第二把锯齿降到 0.38、三角波升到 0.55、起音拉长
到 45ms。**把鼻音拿掉，而不是给鼻音换位置。**

**触控减法**（用户直接提的三条）：
- BOOST 按钮删掉，改成**按住屏幕**加速：320ms 到 5×，再 850ms 到 15×，松手回 1×。手势和看视频拖进度是同一个。
- 图标去掉文字标签与磨砂底框，只留 21px 图形，点击区域仍是 46px。
- 「更多」托盘改 `flex-wrap`，≤420px 隐藏标签——之前五个按钮一行人肉塞满，最左边的图鉴掉出屏幕且点不到。

## v116–v117：选择的连贯性，以及改名为「源义经」

起航点是五个按钮，选中的那个换一层背景——那是状态变化，不是位移。现在有**一个滑动的滑块**在格子之间
平移（`cubic-bezier(.22,1,.36,1)`，500ms），这是大家已经会读的 iOS 语义。

更明显的是天空：`chooseDeparture()` 原来在**一帧里**改 `travel` 并清空 chunk 缓存，背景是硬切的。
现在改成飞过去——`travel` 用 easeInOutCubic 插值，相邻区带约 1 秒、跨得越远越久（上限 2.2 秒），
世界从身边流过去，结束时再调用同一个 `chooseDeparture()` 精确落位。转场中途给 `gateFlash` 0.18，
相当于一次轻微的曝光抬升，不再是黑屏。

APK 更名为**源义经**。
